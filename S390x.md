## 1. Mental models — stop brute-forcing

### 1a. The stub protocol lifecycle

There is one *stub process* per guest mm. Its address space contains the
guest's mappings **plus** a small window at the very top:

```
 host_task_size ─────────────────────────────┐  (your WIP: minus 16MB gap)
   stub_start + STUB_SIZE                    │
   ┌──────────────────────────┐              │
   │ data page 2: sigstack    │ ← sigaltstack, host writes rt_sigframe here
   ├──────────────────────────┤              │  STUB_DATA_PAGES = 2
   │ data page 1: stub_data   │ ← err, syscall_data[], futex, si/mctx off
   ├──────────────────────────┤              │
   │ code page: .__syscall_stub│ ← handlers + stub_signal_restorer
   └──────────────────────────┘              │
   stub_start                 ──────────────┘
   ... guest address space below ...
```

Lifecycle: `start_userspace()` clones `userspace_tramp` which writes
`stub_init_data` into a socketpair and execs `stub_exe`. `real_init()`
reads init_data from fd 0, mmaps the code page and data pages MAP_FIXED
| MAP_SHARED from the kernel-provided fds (so *the UML kernel sees the
same physical pages* — `mm_id.stack` is the kernel-side mapping of
stub_data), sets sigaltstack into the data pages, registers handlers,
then either installs the seccomp filter and traps, or PTRACE_TRACEME +
SIGSTOP.

**Batching:** the kernel queues mmap/munmap requests in
`stub_data.syscall_data[]` and sets `syscall_data_len`. The stub's
`syscall_handler()` replays them with real syscalls *from inside the
target address space* — that is the whole trick of modern UML: the
kernel never ptrace-pokes memory maps in, the stub self-installs them.

**Control transfer back:**
- *ptrace mode:* stub runs `trap_myself()` — an instruction whose signal
  the tracer waits for. The contract is `wait_stub_done()`
  (os-Linux/skas/process.c): loop past SIGALRM/SIGWINCH
  (`STUB_SIG_MASK`), then **accept exactly SIGTRAP** (`STUB_DONE_MASK`);
  anything else → `fatal_sigsegv()`.
- *seccomp mode:* no ptrace at all. Handshake is
  `stub_data.futex`: kernel sets FUTEX_IN_CHILD + FUTEX_WAKE, waits for
  FUTEX_IN_KERN; the stub's `stub_signal_interrupt` does the converse.
  `wait_stub_done_seccomp()` has a 5s timeout backstop with a pidfd
  aliveness check — **when you see its timeout fire with the child still
  alive, the futex the stub is waking is not the futex the kernel is
  waiting on** — i.e. a stub_data addressing bug, not a liveness bug.

**s390 deltas to hold in your head:**
- svc ABI: `svc 0` with nr in r1, args r2–r7, ret r2. All six stub
  wrappers now declare r3–r7 as asm inputs (your fix — verified: futex
  shows `lghi %r1,238; lgr %r2,…; lghi %r3,…; lghi %r4,…; svc 0`).
- `trap_myself` must produce **SIGTRAP under a tracer**. On s390 the
  official breakpoint is opcode `0x0001` (`S390_BREAKPOINT_U16`,
  uapi/asm/ptrace.h:307): native `illegal_op` (arch/s390/kernel/
  traps.c:151) converts exactly that opcode to SIGTRAP/TRAP_BRKPT *iff
  `current->ptrace`*, else SIGILL. The current `.short 0xffff` pair is
  never special-cased → SIGILL → `wait_stub_done` fatal. (In seccomp
  mode nothing traces the stub, so 0x0001 would also SIGILL — fine,
  trap_myself is only reached on the ptrace paths.)
- The 160-byte register save area: an s390x callee stores its saved
  registers into the *caller's* frame at `48(%r15)..159(%r15)` **before**
  decrementing r15. Any "top of stack" you hand to fresh code must
  leave ≥160 bytes of valid memory *above* the initial SP. Your
  `UM_THREAD_START_SP(stack) = top - 176 & ~15` is correct; so is the
  sigaltstack (host builds the frame below the top itself).
- `stub_start(fn)` must move SP **down** by STUB_SIZE because exec puts
  the initial stack exactly where the stub pages will be MAP_FIXED'd.
  Your `-STUB_SIZE` fix is in (disasm: `aghi %r15,-12288`).

### 1b. The two execution modes as data flows

Half the review findings are "the arrow points at the wrong struct
field". Draw the arrows once:

```
PTRACE (SYSEMU) mode — host kernel is the interceptor
  guest syscall ──► host SYSEMU stop ──► ptrace_getregs(NT_PRSTATUS)
                                            │ 27 longs: psw,gprs,acrs,orig_gpr2
                                            ▼
     regs->gp[0..26] + synthetic slots ◄────┘
     HOST_SYSCALLNO ◄── ??? (see ladder P2: gprs[2] mirror, NOT gprs[1])
  guest fault  ──► SIGSEGV stop ──► PTRACE_CONT(child, SIGSEGV)
                     └► stub_segv_handler runs IN the child:
                        GET_FAULTINFO_FROM_MC(mcontext) → writes faultinfo
                        at get_stub_data(); trap_myself(); kernel memcpys
                        it from current_stub_stack().   [blockers 4+5+6 chain]
  resume: ptrace_setregs + put_fp_registers + PTRACE_SYSEMU.

SECCOMP mode — the BPF filter is the interceptor, no ptrace anywhere
  guest syscall ──► SECCOMP_RET_TRAP ──► host delivers SIGSYS to the stub
                     on the sigaltstack (inside stub_data pages)
  stub_signal_interrupt: d->si_offset / d->mctx_offset := where the host
                     put siginfo/uc_mcontext inside sigstack; futex dance.
  kernel side:  regs ◄── get_stub_state → get_regs_from_mc(mcontext)
                nr   ◄── si->si_syscall  (seccomp_data.nr — always right)
                arg1 ◄── gp[HOST_ORIG_GPR2]  ◄── **NOBODY WRITES THIS** (P3)
                faultinfo ◄── siginfo (si_addr, si_code)  — your WIP, refine (P5)
  resume: set_stub_state writes the mcontext in place; stub returns via
          rt_sigreturn FROM THE STUB PAGE with r15 = FRAME BASE (P2a);
          host restore_sigregs merges user PSW bits and reloads everything.
```

Mode decision: your `seccomp_config = 2` for CONFIG_UML_S390 is the
right call *for this host generation*. Two independent reasons: (1) the
modern UML ptrace loop unconditionally uses `PTRACE_SYSEMU` /
`PTRACE_SYSEMU_SINGLESTEP` (os-Linux/skas/process.c) with no
PTRACE_SYSCALL fallback; (2) although *this tree's* s390 uapi defines
PTRACE_SYSEMU 31/32 (arch/s390/include/uapi/asm/ptrace.h:121 — so
future hosts will grow it), your 6.8.0-124 host box demonstrably does
not honor the "stop once at entry, skip execution" contract. So: seccomp
is the supported lane; the ptrace-lane fixes (P-rungs below) are for
correctness-before-posting and for future hosts, not for your boot.

One host-ABI landmine for whenever ptrace mode does run: on s390,
**writing gprs[2] at a syscall stop is not a plain register write** —
host `__poke_user` (arch/s390/kernel/ptrace.c:352) turns it into
`regs->int_code = 0x20000 | (data & 0xffff)`, i.e. a syscall-number
change; and SETREGSET NT_PRSTATUS goes through `__poke_user` per word,
so *every full register restore at a syscall stop rewrites int_code from
r2's low bits*. Mostly harmless for the stub, but remember it when a
"random" restart misbehaves under ptrace mode.

### 1c. PSW discipline

The PSW is two longs: `mask` (state bits) and `addr` (the PC).
Userspace legitimately owns only `PSW_MASK_USER = 0x0000FF0180000000`
(ASC | CC | program mask | EA | BA — uapi/asm/ptrace.h:97). Everything
else (`PER, DAT, IO, EXT, KEY, MCHECK, WAIT, PSTATE, RI`) is
system-owned, and the two host-side consumers *enforce different rules*:

- host `__poke_user` (ptrace.c:337): rejects with -EINVAL any mask whose
  non-user bits differ from `PSW_USER_BITS` (= DAT|IO|EXT|key|MCHECK|
  PSTATE|ASC_PRIMARY, asm/ptrace.h:56), any ASC_HOME, any EA-without-BA.
- host `restore_sigregs` (kernel/signal.c:153): doesn't reject — it
  *merges*: `mask = (current & ~(PSW_MASK_USER|PSW_MASK_RI)) |
  (frame & (PSW_MASK_USER|PSW_MASK_RI-if-allowed))`, then fixes ASC_HOME
  and EA→BA.

**The one rule that kills the whole bug class: never construct a PSW
mask from scratch; always merge the user bits into the mask you already
have.** Your kernel-side `putreg()` already does exactly this — hold it
up as the pattern:

```c
value = (value & UM_S390_PSW_MASK_USER) | UM_S390_PSW_MASK_PSTATE |
        (old_mask & ~UM_S390_PSW_MASK_USER);
```

`restore_mc()` in arch/s390/um/signal.c is the one place still doing
`mask &= USER; mask |= PSTATE` — that strips DAT/IO/EXT/MCHECK, which
`__poke_user` rejects → in ptrace mode every guest sigreturn is fatal.
(In seccomp mode the host's merge quietly repairs it, which is why you
haven't been burned yet.) Fix is rung P4.

Corollary for single-step: the PER bit (1<<62) you set in
`get_mc_from_regs` is **outside PSW_MASK_USER**, so host
`restore_sigregs` throws it away on the very sigreturn that resumes the
guest. Seccomp-mode single-step needs a design, not a bit (deferred, §6).

### 1d. Big-endian traps specific to this port

- **4-vs-8-byte regset objects.** `thread.system_call` is a 4-byte
  regset (host `s390_system_call_set` copies `sizeof(unsigned int)`).
  An 8-byte peek on BE reads the wrong word; an 8-byte poke writes 0
  into it. Your WIP dodged this by abandoning the regset entirely —
  fine — but keep the rule: **on BE, a size-mismatched access is not
  "harmless truncation", it reads the other half.**
- **seccomp_data.instruction_pointer halves.** BPF loads 32-bit words.
  On BE, offset +0 is the HIGH half, +4 the LOW half — your rewrite got
  this right (it was the committed code's fatal bug); one jump-target
  slip remains (rung P?—no: rung 4 below).
- **acrs packing — the done-RIGHT pattern.** acrs are sixteen 32-bit
  cells in a long-indexed frame; on BE, `acrs[2i]` is the *high* half of
  long slot `HOST_ACRS+i`. Every marshal in the tree (`ptrace_getregs`,
  `get_regs_from_mc`, `build_mc`, `restore_mc`, `arch_set_tls`) uses the
  same `(hi<<32)|lo` shape, and user-offsets.c emits both the long index
  and the byte offset so nothing assumes LE. When you need to move any
  other sub-long object through the gp frame, copy this.
- svc immediate vs r1: kernel derives nr from `int_code`, falling back
  to `gprs[1]` only when the svc immediate was 0
  (arch/s390/kernel/syscall.c:113-118). Your host glibc (2.39 cross)
  happens to emit `lghi %r1,NR; svc 0` at *all 518* svc sites — which is
  why your gprs[1] probe held — but `svc N` (N<256, immediate form) is
  legal and historically common. The only nr sources valid for **both**
  encodings: `gprs[2]` at the entry stop (the kernel mirrors nr there
  *before* the tracer stop — syscall.c:119, and the comment at :126
  says this is deliberate ptrace ABI), or PTRACE_GET_SYSCALL_INFO.

### Rung S1 — `get_stub_data()` returns the wrong address  *(review #4 — your top blocker right now)*

`larl %0, 0f` yields the address **of the label**, not a page-aligned
PC — the committed comment lies. Disassembly of your current stub.o:

```
stub_syscall_handler:    larl %r12, .+0x14 ; aghi %r12, 4096   → data+0x14
stub_signal_interrupt:   larl %r12, .+0xf8-…                   → data+0xf8-ish
stub_segv_handler:       larl %r1,  .+0x6  ; aghi %r1,  4096   → data+0x06
```

Every `d->field` access is shifted by a different constant per inline
site. Concretely: the stub wakes/waits on `&d->futex + 0xf8`… while
`wait_stub_done_seccomp` waits on the real `&data->futex` — **this is
your 5-second timeout with a live child.** `si_offset`/`mctx_offset` are
both computed against and stored through the wrong base, so the kernel
reads garbage offsets too.

Fix (mask like x86's `and $PAGE_MASK`; test-assembled, output verified
`larl; nill %rX,61440; aghi %rX,4096`):

```c
static __always_inline void *get_stub_data(void)
{
	unsigned long ret;

	asm volatile (
		"	larl	%0, 0f\n"
		"0:	nill	%0, 0xf000\n"	/* page-align (4K pages) */
		"	aghi	%0, %1\n"
		: "=&d" (ret)
		: "i" (UM_KERN_PAGE_SIZE)
		: "cc");

	return (void *)ret;
}
```

(`nill` masks the low 16 bits with 0xf000 → clears bits 52–63. If you
ever want page-size generality, `risbg %0,%0,0,179,0` zeroes the low 12
with the same effect. Works because all `.__syscall_stub` text lives in
the single code page.)

**Verify (30s):** rebuild stub.o + stub_segv.o, then
`s390x-linux-gnu-objdump -d arch/um/kernel/skas/stub.o | grep -A2 larl` —
every stub-data `larl` must be immediately followed by `nill …,61440`
then `aghi …,4096`. (The one exception: the `larl %r1,
stub_signal_restorer` branch — no mask there, it's a code address.)

### Rung S2 — `stub_signal_return`: r15 must be the FRAME BASE, not the siginfo  *(new bug in your WIP)*

Ground truth (arch/s390/kernel/signal.c:99, and `sys_rt_sigreturn` at
:239): the host locates the frame as `(struct rt_sigframe *)
regs->gprs[15]`, and the frame layout is `{callee_used_stack[160],
__u16 svc_insn, siginfo info, ucontext_extended uc}` — so
`offsetof(rt_sigframe, info) == 168` (160 + 2, padded to siginfo's
8-byte alignment; fixed uapi, vector extensions only ever append to
sregs_ext). The generic stub calls `stub_signal_return(info)`; **on
arm64 info == frame base; on s390 it is frame+168.** Your current
`lgr %%r15, %0` therefore hands rt_sigreturn a frame shifted by 168 →
`restore_sigregs` reads garbage → precisely the class of "resurrected
guest SP=0" you observed (though what you observed predates the
arg-load fix, so re-measure before trusting old symptoms).

```c
static __always_inline void stub_signal_return(void *info)
{
	/*
	 * Host rt_sigreturn takes the frame from %r15
	 * (arch/s390/kernel/signal.c sys_rt_sigreturn). The handler's
	 * siginfo pointer sits at frame+168: 160-byte callee area +
	 * u16 svc_insn, padded to siginfo's 8-byte alignment. Fixed ABI.
	 */
	unsigned long frame = (unsigned long)info - 168;

	asm volatile (
		"	lgr	%%r15, %0\n"
		"	larl	%%r1, stub_signal_restorer\n"
		"	br	%%r1\n"
		:: "d" (frame) : "r1", "memory");
	__builtin_unreachable();
}
```

Alternative worth knowing: the *empty* body (as committed) is also
theoretically correct on s390 — the handler's own epilogue restores
r15 = frame base and `br %r14` where r14 = SA_RESTORER = the in-stub
restorer, exactly the x86 model. But your explicit-jump version is
what arm64 does, is robust against the compiler's choice of epilogue,
and with `-168` it is right. Pick one; don't keep the comment claiming
"the handler's siginfo* IS the frame base" — on s390 it isn't.

**Verify (30s):** `objdump -d stub.o`: (a) the tail of
stub_signal_interrupt must compute `r15 = r_info − 168` (e.g.
`aghik %r15,%rX,-168` or `lay`) before `larl %r1,stub_signal_restorer;
br %r1`; today it shows a bare `lgr %r15,%r11`. (b)
`stub_signal_restorer` must remain exactly `lghi %r1,173; svc 0`
— no prologue, no stack use (it already is: verified).

### Rung S4 — seccomp filter: dead end-bound check  *(residual of review #10a — your BE rewrite is otherwise right)*

In your stub_exe.c filter, instruction i3
`BPF_JUMP(JGE, start_lo, 1, 4)` has jt=1, which jumps **over** i4 (the
`ip < end` check) straight to the arch check: i4 is unreachable and any
IP above the stub window (same upper half) is treated as in-stub. With
the 16MB gap the exposed range is the old host-stack area — low risk,
but it's a filter-correctness bug and a reviewer magnet. Corrected
index map (fall through to the end check):

```
 0  LD  ip_hi
 1  JEQ hi==start_hi   ? +0 : +6   → no: 8 (TRAP, guest syscall)
 2  LD  ip_lo
 3  JGE ip_lo>=start_lo ? +0 : +4  → no: 8 (TRAP)          [jt was 1 — make it 0]
 4  JGE ip_lo>=end_lo   ? +3 : +0  → yes: 8 (TRAP)
 5  LD  arch
 6  JEQ arch==native    ? +2 : +0  → yes: 9
 7  RET KILL_PROCESS
 8  RET TRAP
 9  LD  nr … allowlist … 16 RET KILL / 17 RET ALLOW
```

Note the committed x86 filter confines the allowlist to the **code page
only** (mask 0xfffff000 == one page); your widening to the whole
STUB_SIZE window is unnecessary — the handler's *IP* during
futex/recvmsg is in the code page; the sigaltstack in the data pages is
where r15 points, and seccomp checks IP, not SP. Either keep the window
and fix jt, or narrow back to the code page; narrowing is the smaller
posting-time diff against x86.
**Verify (60s):** re-derive each jump target by hand against the table
above — with 18 instructions this is genuinely a one-minute check; every
JGE/JEQ target must land on 8 (TRAP), 7/16 (KILL), or the next check.

### Rung S5 — faultinfo: classify from si_code, drop the retry hack  *(review #6 + the FAULT_WRITE major, replacing your DIVERGES approach)*

Your seccomp-path fill (`fi.addr = si->si_addr`) is right and stays.
Two refinements, both anchored in native code:

**(1) error_code from si_code, not a constant.** The host computes
si_code from the TEID: write-to-protected → `SEGV_ACCERR`, unmapped →
`SEGV_MAPERR`. Native s390 treats *protection exception ⇒ write fault*
(arch/s390/mm/fault.c:284-292: `is_write → access = VM_WRITE`). Mirror
it:

```c
	regs->faultinfo.addr = (unsigned long)si->si_addr;
	regs->faultinfo.error_code =
		(si->si_code == SEGV_ACCERR) ? 0x04 : 0x11;
	regs->faultinfo.trap_no = regs->faultinfo.error_code;
```

and in sysdep/faultinfo.h:

```c
#define FAULT_WRITE(fi) ((fi).error_code == 0x04)
```

**(2) why your `#ifndef HAVE_RELIABLE_FAULT_WRITE` retry-on-EFAULT in
trap.c cannot stay:** the killer case doesn't return -EFAULT. A guest
*store* to a present read-only page (COW break, or UML's own dirty-bit
emulation which deliberately maps clean pages RO) that is misclassified
as a read makes `handle_page_fault` **succeed without doing anything**
(pte present + readable), the host mapping stays RO, the store refaults
— an infinite fault loop with err==0, which your `err == -EFAULT` guard
never sees. Even fresh-stack stores livelock via the zero-page: store →
MAPERR → read-classified → zero page mapped RO → store refaults →
ACCERR → (with the si_code fix) write → COW breaks → converges in two
rounds. With the constant 0x11 it never converges. The si_code fix
solves growth *and* COW; then delete the trap.c hunk and the three
`HAVE_RELIABLE_FAULT_WRITE` header additions — shared-file churn you no
longer need. (Edge: an exec-fault on IEP hosts also reports ACCERR and
would be write-classified; outcome for the guest is SEGV_ACCERR either
way, same as native.)

**Verify (60s, no boot):** this is milestone-checked (rung M5 below),
but statically: `grep -n "error_code" arch/um/os-Linux/skas/process.c
arch/s390/um/shared/sysdep/faultinfo.h` must show si_code feeding 0x04,
and `SEGV_IS_FIXABLE` covering both 0x04 and 0x11 (it does). The
lingering build warning `stub_segv.c: unused variable 'uc'` is the
reminder that the *ptrace-mode* faultinfo macro is still a zero-stub
(rung P5).

### Rung S6 — `kernel_longjmp` discards `val`  *(new — the review and your WIP both missed it)*

Disassembly of your fixed-offsets setjmp_64.o:

```
kernel_longjmp: lgr %r5,%r2 ; lgfr %r4,%r3 ; lghi %r2,1 ; ltgr %r4,%r4
                jne 0f ; lghi %r4,1 ; 0: lmg…lg…lg ; br %r14
```

`val` goes to r4 and dies there; **r2 = 1 always**. Consumers that need
distinct values: `start_idle_thread`'s `switch (setjmp(initial_jmpbuf))`
— `INIT_JMP_HALT` (2) and `INIT_JMP_REBOOT` (3) will be dispatched as
`INIT_JMP_CALLBACK` (1) and call a stale `cb_proc` → crash at
halt/reboot/panic paths. Boot mostly works by luck (everything else
jumps with 1). Fix:

```
SYM_FUNC_START(kernel_longjmp)
	lgr	%r5,%r2			/* buf */
	lgfr	%r2,%r3			/* return value = val */
	ltgr	%r2,%r2
	jne	0f
	lghi	%r2,1			/* longjmp(x,0) returns 1 */
0:	lmg	%r6,%r13,0(%r5)
	lg	%r14,64(%r5)
	lg	%r15,72(%r5)
	br	%r14
SYM_FUNC_END(kernel_longjmp)
```

**Verify (60s):** objdump must show `lgfr %r2,%r3` (val into the return

10-line main calling `kernel_setjmp` once, `kernel_longjmp(buf, 7)`
from a helper — must print 7, and a second run with val=0 must print 1.

### Rung S7 — syscall restart never restores r2  *(new — same family as the arm64 orig-x0 miss the review DID catch)*

Native: every `-ERESTART*` path does `regs->gprs[2] = regs->orig_gpr2`
before rewinding the PSW (arch/s390/kernel/signal.c:469, :491, :500).
UML generic does `PT_REGS_ORIG_SYSCALL(regs) = nr` +
`PT_REGS_RESTART_SYSCALL(regs)`; on s390 the former writes the dead
HOST_SYSCALLNO slot (helps nothing at replay — the re-executed `svc`
re-derives nr itself) and the latter only rewinds the IP — so the
replayed syscall runs with **arg1 = -ERESTARTSYS**. Fix in
arch/s390/um/asm/ptrace.h:

```c
#define UPT_RESTART_SYSCALL(r) do {				\
	(r)->gp[HOST_GPR0 + 2] = (r)->gp[HOST_ORIG_GPR2];	\
	UPT_IP(r) -= 2;						\
} while (0)
```

(-2 is exact for svc; native uses the int_code ilc but svc is always
2 bytes.) Depends on rung S3 so ORIG_GPR2 holds truth in seccomp mode.
`-ERESTART_RESTARTBLOCK` remains wrong even after this (the replayed
svc re-runs the *original* nr instead of `restart_syscall`) — that
needs the vdso-trampoline design, deferred §6.
**Verify:** code-inspection rung; functional check rides milestone M6
(a SIGALRM-interrupted nanosleep in the guest resumes with a sane
remaining time instead of -EINVAL/EFAULT).

## 6. Deferred-but-coming — decide once, here

- **VXRS + HWCAP masking.** Distro s390x userspace is built ≥z13;
  guests told `vx` via the unmasked host HWCAP *will* use vector regs,
  but v0 preserves only the 136-byte fp frame across traps and signal
  frames → silent vector-state corruption between guest tasks.
  Decision: for v0/RFC, **mask HWCAP_S390_VXRS (+VXRS_EXT, VXRS_EXT2,
  NNPA-adjacent bits)** in elf_aux_hwcap, mirroring arm64's PAC/SVE
  masking, and say so in the commit; wiring NT_S390_VXRS_* + `_sigregs_ext`
  + a 512-byte-larger mcontext round-trip is a straight but sizeable
  follow-up (host mcontext already carries vxrs; the frame layout is in
  native signal.c). Also stop the cpuinfo facilities passthrough from
  contradicting the mask.
- **ARCH_DLINFO restore.** The infrastructure (um_vdso mapping,
  um_minsigstksz, the AT_VECTOR_SIZE analysis in the elf.h comment) is
  all present; only the `#define ARCH_DLINFO` with two NEW_AUX_ENTs is
  missing. Two lines mirroring x86_um/arm64_um. Until then the vDSO
  page is mapped but undiscoverable and AT_MINSIGSTKSZ absent.
- **SA_RESTORER honoring.** Native: `if (SA_RESTORER) restorer =
  sa_restorer else VDSO_SYMBOL(rt_sigreturn)` (signal.c:377-380). UML
  signal.c should do the same with um_vdso_sigreturn as fallback —
  three lines; matters for CRIU, sanitizers, and anything replacing the
  restorer. While there: native also writes the stack **backchain**
  (`frame[0] = old r15`) and `gprs[5] = last_break`; the backchain is
  cheap fidelity worth adding for unwinders.
- **udelay.** Copy the x86/um form: `__udelay(us)` →
  `__const_udelay(us * 0x10c7)`; `__const_udelay(x)` →
  `__delay(((x * HZ * loops_per_jiffy) >> 32) + 1)`. Current formula is
  ~430× short (missing HZ, decimal 1000 vs 0x10c7).
- **csum carry.** Accumulate into `u64`, fold once at the end
  (`sum = (sum >> 32) + (u32)sum` twice, then 16-bit fold). The current
  u32 accumulator drops end-around carries on buffers >~128KB or large
  incoming partial sums — exactly the sizes NFS/iSCSI hand it.
- **sigaction/sigsuspend/sigreturn (67/72/119).** The tbl serves them
  `common`; the alias file ni-stubs them with a rationale comment
  ("nothing sane calls them") that is defensible for glibc but not for
  static binaries from other libcs. Cheapest correct: wire
  sys_sigsuspend (generic exists) and old sigaction via the compat-free
  `__ARCH_WANT_SYS_SIGPROCMASK`-family helpers; or keep the ni-stubs
  and defend them in the cover letter. Decide before Cc'ing linux-s390 —
  Heiko will ask.
- **PTRACE_PEEKUSR_AREA / POKEUSR_AREA.** s390 gdb/strace use the
  0x5000 area calls as their primary register channel. `subarch_ptrace`
  returning -EIO means *guest* debugging is dead on arrival for native
  tools. Implement over the existing getreg/putreg (area = offset/len
  loop) — mechanical, ~40 lines, big usability win for the RFC.
- **Seccomp single-step.** The PER bit dies at host sigreturn (§1c).
  Options: (a) declare single-step unsupported in seccomp mode for v0
  (document + make PTRACE_SINGLESTEP on guests return -EIO cleanly);
  (b) breakpoint-injection scheme (plant 0x0001 at next-IP like uml/x86
  once did); (c) run the *one* stepped task in ptrace mode. (a) is
  honest for the RFC; (b) is where this ends up long-term.
- **-ERESTART_RESTARTBLOCK.** After S7, restarts of nanosleep-class
  calls still replay the original nr. Native solves it by pointing the
  PSW at a vdso `restart_syscall` trampoline (signal.c:493-496 +
  __do_syscall's arch_data check). The um vdso already exists — add a
  `svc __NR_restart_syscall` symbol next to the sigreturn trampoline
  and mirror the native flow in the s390 UPT_/PT_REGS_ macros.
- **asm `_start` for stub_exe.** The `naked` attribute is ignored
  (warning in every build); today's GCC emits an FPR-save prologue that
  happens not to touch memory. That is luck, not ABI. Write the
  8-instruction asm `_start` (the stub_start body) before posting.
- **Series hygiene at rebase time** (from the review, unchanged):
  signal.h include chain so every commit builds; fold 4197af5af364 and
  the shared STUB_MMAP/faultinfo hunks back into S1; jargon sweep
  (DESIGN§/F-s*/P-numbers are in Kconfig help and ~10 s390 comments);
  SoB/authorship; s390-vs-s390x naming (`SUBARCH=s390x` currently
  *fails* — only `SUBARCH=s390` configures; either map it in
  arch/um/Makefile like x86 does i386/x86_64 or document).
